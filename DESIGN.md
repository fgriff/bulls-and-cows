# Дизайн и архитектура (DESIGN)

## Структуры данных и алгоритмы

### 1. Состояние игры и история попыток

Для хранения состояния игры используется **размеченное объединение** (discriminated union) в `src/core/state.ts`. Это позволяет четко разделить три фазы игры:

- `settings` — экран настроек (нет секрета, нет истории).
- `playing` — идет раунд (есть секрет, время старта и история попыток).
- `finished` — игра завершена (добавлено время окончания).

**Почему так:** использование строгих типов гарантирует, что мы не сможем случайно запросить время окончания игры, пока она еще идет. Это делает код безопасным на уровне компилятора.

**История попыток** — это обычный массив (`readonly Attempt[]`), который обновляется иммутабельно. Каждая запись содержит попытку игрока и результат (`bulls`/`cows`). Чтобы избежать дублирования, функция `appendAttempt` проверяет, была ли уже такая попытка (с приведением к нижнему регистру для hex-системы).

### 2. Алгоритм `evaluateGuess` (Сравнение попытки)

Алгоритм работает в два этапа через методы массивов (`filter`, `reduce`), без ручных циклов со счетчиками:

1.  **Поиск «быков» (bulls):** Проходим по массивам и сравниваем символы на одинаковых индексах. Количество совпадений — это `bulls`.
2.  **Поиск «коров» (cows):** Из обоих массивов удаляем символы, которые уже стали «быками». Оставшиеся символы попытки ищут совпадения в остатке секрета. Так как в секрете цифры уникальны, каждая оставшаяся цифра попытки может дать максимум одну «корову».

### 3. Алгоритм `countPossibleSecrets` (Количество комбинаций)

Используется рекурсивная формула перестановок: `P(length, base) = base * P(length - 1, base - 1)`.

- Базовый случай: если `length = 0`, возвращаем `1`. Если `length > base`, возвращаем `0` (невозможно набрать уникальные цифры).
- **Мемоизация:** Результаты вычислений сохраняются в `Map` по ключу `${length}:${base}`. Функция вызывается при каждом открытии настроек, и мемоизация избавляет от повторных вычислений.

## Сложность (Big O)

- **`generateSecret(length, base)` — O(length²)**.  
  _Обоснование:_ Функция рекурсивно набирает уникальные символы. На каждом шаге она проверяет, есть ли уже такой символ в накопленном массиве (это операция O(length)), и создает новый массив (тоже O(length)). В худшем случае количество вызовов `random` также стремится к O(length²), если выпадают дубли. Для игры длина ограничена 6 символами, поэтому это константное время.
- **`evaluateGuess(secret, guess)` — O(n²)**, где _n_ — длина строки.  
  _Обоснование:_ Поиск «быков» — O(n). Формирование остатков — O(n). Поиск «коров» через `reduce` с `indexOf`/`slice` в худшем случае дает O(n²). При длине до 6 символов это выполняется мгновенно.
- **`isValidGuess(guess, length, base)` — O(n)**, где _n_ — длина попытки.  
  _Обоснование:_ Проверка длины — O(1). Проверка каждого символа валидатором — O(n). Проверка уникальности через `Set` — O(n).
- **`countPossibleSecrets(length, base)` — O(length)** при первом вызове и **O(1)** при повторном.  
  _Обоснование:_ Глубина рекурсии равна `length` (максимум 6). Благодаря мемоизации, повторный вызов с теми же аргументами (например, при возврате на экран настроек) сразу берет значение из `Map`.

## Принципы чистого кода

1.  **Единственная ответственность (SRP)**
    - `src/core/createDigitValidator.ts` — отвечает только за валидацию одного символа.
    - `src/core/evaluateGuess.ts` — только за сравнение.
    - `src/core/state.ts` — только за переходы состояний.
2.  **DRY (Don't Repeat Yourself)**
    - Все алфавиты систем счисления хранятся в одном месте — `DIGITS_BY_BASE` в `src/core/types.ts`.
    - Нормализация регистра (`toLowerCase`) для hex-системы применяется в `createDigitValidator`, `isValidGuess` и `evaluateGuess`.
3.  **Каррирование**
    - Функция `createDigitValidator(base)` в `src/core/createDigitValidator.ts` — это каррированная фабрика. Она возвращает функцию-предикат, которая используется в двух местах: в `isValidGuess` (для проверки всей строки) и в `src/ui/board.ts` (для блокировки недопустимых символов при вводе).
4.  **Функции высшего порядка (HOF)**
    - **Передача функций как аргументов:** В `src/core/generateSecret.ts` функция `generateSecret` принимает функцию `random` как аргумент. В `src/core/state.ts` функции `startGame` и `submitGuess` принимают функцию `clock`. Это позволяет легко подменять источники данных в тестах.
    - **Использование коллбэков в методах массивов:** В `src/core/evaluateGuess.ts` мы передаем функции-стрелки в `filter` и `reduce` для декларативного подсчета быков и коров, избегая ручных циклов `for`.
5.  **Иммутабельность**
    - В `src/core/history.ts` функция `appendAttempt` возвращает новый массив `[...history, attempt]` вместо мутации (`push`).
    - В `src/core/state.ts` все переходы (`startGame`, `submitGuess`) возвращают новые объекты состояния, не изменяя старые.
6.  **Мемоизация**
    - В `src/core/countPossibleSecrets.ts` используется `Map` для кэширования результатов тяжелых рекурсивных вычислений.
7.  **Инъекция зависимостей (Dependency Injection)**
    - Все побочные эффекты (случайность, время, хранилище) передаются в функции явно: `random` в `generateSecret`, `clock` в `startGame`, `storage` в `createApp`. Благодаря этому ядро игры (папка `src/core`) остается полностью чистым и не зависит от браузера.
